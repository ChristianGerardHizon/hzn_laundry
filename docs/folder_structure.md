# Folder Structure

This document describes the architecture and folder organization for the HZN Laundry Flutter application.

---

## Overview

The project follows a **feature-based clean architecture** with three distinct layers:

```
lib/
├── main.dart                 # App entry point
└── src/
    ├── core/                 # Shared functionality across features
    └── features/             # Feature modules organized by domain
```

## Layer Details

### Data Layer

The data layer handles all external data operations.

**Simple features (single DTO/repository):**
```
data/
├── [feature]_dto.dart
├── [feature]_dto.mapper.dart
├── [feature]_repository.dart
└── [feature]_repository.g.dart
```

**Complex features (multiple DTOs/repositories):**
```
data/
├── dto/
│   ├── [feature]_dto.dart          # Response DTO (API -> Domain)
│   ├── [feature]_dto.mapper.dart
│   └── create_[feature]_dto.dart   # Request DTO (Domain -> API)
└── repositories/
    ├── [feature]_repository.dart
    └── [feature]_repository.g.dart
```

> **When to use subfolders:** Create `dto/` and `repositories/` subfolders when a feature has 3+ DTOs or 2+ repositories. This improves organization and makes the data layer easier to navigate.

#### DTOs (Data Transfer Objects)

DTOs are used to decouple API data structures from domain entities. They handle serialization/deserialization and data transformation.

**Combined DTO Pattern (Response + Request in one class):**

```dart
@MappableClass()
class EmployeeAttendanceDto with EmployeeAttendanceDtoMappable {
  final String id;
  final String collectionId;
  final String collectionName;
  final String employee;
  final String? date;
  final bool isPresent;
  final String? notes;
  final String? created;
  final String? updated;

  const EmployeeAttendanceDto({
    required this.id,
    required this.collectionId,
    required this.collectionName,
    required this.employee,
    this.date,
    this.isPresent = true,
    this.notes,
    this.created,
    this.updated,
  });

  /// Creates DTO from PocketBase RecordModel
  factory EmployeeAttendanceDto.fromRecord(RecordModel record) {
    final json = record.toJson();
    return EmployeeAttendanceDto(
      id: json['id'] as String? ?? '',
      collectionId: json['collectionId'] as String? ?? '',
      collectionName: json['collectionName'] as String? ?? '',
      employee: json['employee'] as String? ?? '',
      date: json['date'] as String?,
      isPresent: json['isPresent'] as bool? ?? true,
      notes: json['notes'] as String?,
      created: json['created'] as String?,
      updated: json['updated'] as String?,
    );
  }

  /// Converts DTO to domain entity
  EmployeeAttendance toEntity() {
    return EmployeeAttendance(
      id: id,
      employee: employee,
      date: date != null ? DateTime.tryParse(date!) ?? DateTime.now() : DateTime.now(),
      isPresent: isPresent,
      notes: notes,
      created: created != null ? DateTime.tryParse(created!) : null,
      updated: updated != null ? DateTime.tryParse(updated!) : null,
    );
  }

  /// Converts entity to JSON for create/update operations (static method)
  static Map<String, dynamic> toCreateJson(EmployeeAttendance record) {
    return {
      'employee': record.employee,
      'date': record.date.toIso8601String(),
      'isPresent': record.isPresent,
      'notes': record.notes,
    };
  }
}
```

**Key DTO Concepts:**
- `fromRecord(RecordModel)` - Factory to create DTO from PocketBase record
- `toEntity()` - Instance method to convert DTO to domain entity
- `toCreateJson(Entity)` - **Static method** to convert entity to API payload (avoids conflict with dart_mappable's generated `toJson()`)
- Handle type conversions (String dates -> DateTime, num -> formatted String)
- Isolate API field names from domain layer
- Use `@MappableClass()` for serialization support

#### Repository Pattern

Repositories follow the **abstract interface + implementation** pattern with FutureEither for type-safe error handling.

```dart
/// Repository interface for employee attendance records.
abstract class EmployeeAttendanceRepository {
  /// Fetches all attendance records for an employee.
  FutureEither<List<EmployeeAttendance>> fetchByEmployee(String employeeId);

  /// Fetches a single attendance record by ID.
  FutureEither<EmployeeAttendance> fetchOne(String id);

  /// Creates a new attendance record.
  FutureEither<EmployeeAttendance> create(EmployeeAttendance record);

  /// Updates an existing attendance record.
  FutureEither<EmployeeAttendance> update(EmployeeAttendance record);

  /// Deletes an attendance record.
  FutureEither<void> delete(String id);
}

/// Provider for the employee attendance repository.
@Riverpod(keepAlive: true)
EmployeeAttendanceRepository employeeAttendanceRepository(Ref ref) {
  return EmployeeAttendanceRepositoryImpl(ref.watch(pocketbaseProvider));
}

/// Implementation of the employee attendance repository.
class EmployeeAttendanceRepositoryImpl implements EmployeeAttendanceRepository {
  final PocketBase _pb;

  EmployeeAttendanceRepositoryImpl(this._pb);

  RecordService get _collection =>
      _pb.collection(PocketBaseCollections.employeeAttendances);

  @override
  FutureEither<List<EmployeeAttendance>> fetchByEmployee(String employeeId) async {
    return TaskEither.tryCatch(
      () async {
        final records = await _collection.getFullList(
          filter: 'employee = "$employeeId"',
        );
        return records
            .map((r) => EmployeeAttendanceDto.fromRecord(r).toEntity())
            .toList();
      },
      Failure.handle,
    ).run();
  }

  @override
  FutureEither<EmployeeAttendance> create(EmployeeAttendance record) async {
    return TaskEither.tryCatch(
      () async {
        final created = await _collection.create(
          body: EmployeeAttendanceDto.toCreateJson(record),
        );
        return EmployeeAttendanceDto.fromRecord(created).toEntity();
      },
      Failure.handle,
    ).run();
  }

  @override
  FutureEither<void> delete(String id) async {
    return TaskEither.tryCatch(
      () async {
        await _collection.delete(id);
      },
      Failure.handle,
    ).run();
  }
  // ... update, fetchOne follow same pattern
}
```

**Key Repository Concepts:**
- **Abstract interface** defines the contract (easy to mock for testing)
- **Implementation class** contains PocketBase-specific logic
- Returns `FutureEither<T>` (typedef for `Future<Either<Failure, T>>`)
- Uses `TaskEither.tryCatch()` from fpdart for clean async error handling
- `Failure.handle` - Standard error handler that wraps exceptions
- Provider returns the interface type, not implementation
- `@Riverpod(keepAlive: true)` keeps repository alive across navigation

### Domain Layer

The domain layer contains business entities and models.

```
domain/
└── [feature].dart
```

**Entity Pattern:**

```dart
@MappableClass()
class Employee with EmployeeMappable {
  const Employee({
    required this.id,
    required this.name,
    this.baseSalary = 0,
    this.isDeleted = false,
    this.created,
    this.updated,
  });

  /// PocketBase record ID.
  final String id;

  /// Employee name.
  final String name;

  /// Base salary amount.
  final num baseSalary;

  /// Soft delete flag.
  final bool isDeleted;

  /// Creation timestamp.
  final DateTime? created;

  /// Last update timestamp.
  final DateTime? updated;

  /// Formatted salary display.
  String get salaryDisplay => '₱${baseSalary.toStringAsFixed(2)}';
}
```

**Key Concepts:**
- Uses `@MappableClass()` from dart_mappable for serialization
- A `part '[feature].mapper.dart';` directive pulls in the generated mapper
- Computed getters (like `salaryDisplay` above) live directly on the entity
- Enums for fixed values live in their own file (e.g. `deduction_type.dart`)

#### Application Layer (Services)

The application layer contains business logic, use cases, and orchestration between repositories. Services coordinate complex operations that involve multiple entities or require business rules.

**Service Pattern:**

```dart
@riverpod
class EmployeeService extends _$EmployeeService {
  @override
  EmployeeService build() => this;

  /// Creates an employee with an associated first attendance record.
  Future<Either<Failure, Employee>> createEmployeeWithFirstAttendance({
    required CreateEmployeeDto dto,
  }) async {
    final employeeRepo = ref.read(employeeRepositoryProvider);
    final attendanceRepo = ref.read(employeeAttendanceRepositoryProvider);

    final employeeResult = await employeeRepo.create(dto);

    return employeeResult.fold(
      (failure) => Left(failure),
      (employee) async {
        final attendanceDto = CreateEmployeeAttendanceDto(
          employee: employee.id,
          date: DateTime.now(),
          isPresent: true,
        );
        await attendanceRepo.create(attendanceDto);

        return Right(employee);
      },
    );
  }

  /// Calculates an employee's effective monthly salary after deductions.
  Future<num> getEffectiveMonthlySalary(String employeeId, DateTime month) async {
    final employee = await ref.read(employeeProvider(employeeId).future);
    final deductions = await ref.read(employeeDeductionControllerProvider(employeeId).future);

    final applicable = deductions.where((d) => d.isApplicableFor(month));
    final total = applicable.fold<num>(
      0,
      (sum, d) => sum + d.computeAmount(employee?.baseSalary ?? 0),
    );

    return (employee?.baseSalary ?? 0) - total;
  }
}
```

**Key Application Layer Concepts:**
- Contains business logic that spans multiple repositories
- Orchestrates complex operations (create with related entities)
- Implements use cases (payroll calculation, transfer, archive)
- Calculates derived data and statistics
- Keeps controllers thin and focused on UI state
- Uses `@riverpod` for dependency injection

**When to Use Application Layer:**
| Use Application Layer | Use Repository Directly |
|-----------------------|-------------------------|
| Multi-entity operations | Simple CRUD |
| Business rule validation | Single entity fetch |
| Complex calculations | List/filter queries |
| Workflow orchestration | Basic create/update |

#### Controllers

Controllers manage UI state and delegate to repositories. Two main patterns are used:

**Standard Controller (keepAlive):**

```dart
/// Controller for managing the employees list.
@Riverpod(keepAlive: true)
class EmployeesController extends _$EmployeesController {
  EmployeeRepository get _repository => ref.read(employeeRepositoryProvider);

  @override
  Future<List<Employee>> build() async {
    final result = await _repository.fetchAll();
    return result.fold(
      (failure) => throw failure,
      (employees) => employees,
    );
  }

  /// Refreshes the employees list.
  Future<void> refresh() async {
    state = const AsyncLoading();
    final result = await _repository.fetchAll();
    state = result.fold(
      (failure) => AsyncError(failure, StackTrace.current),
      (employees) => AsyncData(employees),
    );
  }

  /// Creates a new employee with optimistic update.
  Future<bool> createEmployee(Employee employee) async {
    final result = await _repository.create(employee);
    return result.fold(
      (failure) => false,
      (newEmployee) {
        final currentList = state.value ?? [];
        state = AsyncData([newEmployee, ...currentList]);
        return true;
      },
    );
  }
}
```

**Family Controller (parameterized state):**

```dart
/// Controller for managing attendance records for a specific employee.
/// This is a family provider - each employee has its own attendance list state.
@riverpod
class EmployeeAttendanceController extends _$EmployeeAttendanceController {
  EmployeeAttendanceRepository get _repository =>
      ref.read(employeeAttendanceRepositoryProvider);

  @override
  Future<List<EmployeeAttendance>> build(String employeeId) async {
    final result = await _repository.fetchByEmployee(employeeId);
    return result.fold(
      (failure) => throw failure,
      (records) => records,
    );
  }

  Future<bool> createRecord(EmployeeAttendance record) async {
    final result = await _repository.create(record);
    return result.fold(
      (failure) => false,
      (newRecord) {
        final currentList = state.value ?? [];
        state = AsyncData([newRecord, ...currentList]);
        return true;
      },
    );
  }
}

/// Provider for a single employee by ID.
@riverpod
Future<Employee?> employee(Ref ref, String id) async {
  final repository = ref.read(employeeRepositoryProvider);
  final result = await repository.fetchOne(id);
  return result.fold(
    (failure) => null,
    (employee) => employee,
  );
}
```

**Key Controller Concepts:**
- `@Riverpod(keepAlive: true)` - State persists across navigation (use for main lists)
- `@riverpod` (lowercase) - State is disposed when no longer watched (use for detail views)
- **Family providers** - Use `build(String id)` parameter for scoped state
- `result.fold()` - Handle Either<Failure, T> from repository
- **Optimistic updates** - Update local state immediately after successful mutation
- Return `bool` from mutations to indicate success/failure to UI

#### Pages

**List Page Pattern with AsyncValue.when:**

```dart
class EmployeesListPage extends ConsumerWidget {
  const EmployeesListPage({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final employeesAsync = ref.watch(employeesControllerProvider);

    return Scaffold(
      appBar: AppBar(title: const Text('Employees')),
      body: employeesAsync.when(
        loading: () => const Center(child: CircularProgressIndicator()),

              const Icon(Icons.error_outline, size: 48),
```

```dart
class EmployeeDetailPage extends ConsumerWidget {
  const EmployeeDetailPage({
    super.key,
    required this.employeeId,
  });

  final String employeeId;

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final employeeAsync = ref.watch(employeeProvider(employeeId));

    if (employeeAsync.isLoading) {
      return const Scaffold(
        body: Center(child: CircularProgressIndicator()),
      );
    }

    if (employeeAsync.hasError) {
      return Scaffold(
        appBar: AppBar(title: const Text('Employee Details')),
        body: Center(child: Text('Error loading data')),
      );
    }

    final employee = employeeAsync.value;

    if (employee == null) {
      return Scaffold(
        appBar: AppBar(title: const Text('Employee Details')),
        body: const Center(child: Text('Not found')),
      );
    }

    return _buildContent(context, employee);
  }
}
```

**Tab Widget with Family Provider:**

```dart
class AttendanceTab extends HookConsumerWidget {
  const AttendanceTab({super.key, required this.employee});

  final Employee employee;

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final recordsAsync = ref.watch(employeeAttendanceControllerProvider(employee.id));

    return recordsAsync.when(
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (error, stack) => _ErrorState(
        onRetry: () => ref.read(employeeAttendanceControllerProvider(employee.id).notifier).refresh(),
      ),
      data: (records) => RefreshIndicator(
        onRefresh: () => ref.read(employeeAttendanceControllerProvider(employee.id).notifier).refresh(),
        child: records.isEmpty
            ? _EmptyState(onAdd: () => _showAddSheet(context, ref))
            : ListView.builder(
                itemCount: records.length,
                itemBuilder: (context, index) => AttendanceCard(record: records[index]),
              ),
      ),
    );
  }

  void _showAddSheet(BuildContext context, WidgetRef ref) {
    showModalBottomSheet(
      context: context,
      isScrollControlled: true,
      builder: (context) => AddAttendanceSheet(
        employeeId: employee.id,
        onSave: (record) async {
          return await ref
              .read(employeeAttendanceControllerProvider(employee.id).notifier)
              .createRecord(record);
        },
      ),
    );
  }
}
```

## Routing Structure

Routes are organized by domain with type-safe navigation:

```dart
// router.dart
final router = GoRouter(
  routes: [
    ShellRoute(
      builder: (context, state, child) => AdaptiveShell(child: child),
      routes: [
        ...managementRoutes,
        ...organizationsRoutes,
        ...usersRoutes,
        ...productsRoutes,
        ...servicesRoutes,
        ...salesRoutes,
        ...settingsRoutes,
      ],
    ),
  ],
);

// users.routes.dart
@TypedGoRoute<UsersRoute>(
  path: '/management/users',
  routes: [
    TypedGoRoute<UserDetailRoute>(path: ':id'),
  ],
)
class UsersRoute extends GoRouteData {
  @override
  Widget build(BuildContext context, GoRouterState state) => const UsersPage();
}
```

## Code Generation

The project uses build_runner for code generation:

```bash
# Run all generators (always use --low-resources-mode, per CLAUDE.md)
dart run build_runner build --delete-conflicting-outputs --low-resources-mode
```

**Generated Files:**
- `*.mapper.dart` - dart_mappable serialization
- `*.g.dart` - Riverpod providers
- `*.routes.g.dart` - Type-safe routes (from `@TypedGoRoute`)
- `strings_en.g.dart` / `strings_tl.g.dart` - Localization (from `dart run slang`)

**Generator Annotations:**
- `@MappableClass()` - Entity serialization
- `@riverpod` / `@Riverpod(keepAlive: true)` - Provider generation
- `@TypedGoRoute` - Route generation

## Summary

| Aspect | Pattern |
|--------|---------|
| Architecture | Feature-based Clean Architecture (4 layers) |
| State Management | Hooks Riverpod with code generation (`@riverpod`) |
| Navigation | GoRouter with type-safe routes (`@TypedGoRoute`) |
| Backend | PocketBase (BaaS) |
| Serialization | dart_mappable (`@MappableClass`) |
| Forms | flutter_form_builder |
| Error Handling | `FutureEither<T>` with fpdart (`TaskEither.tryCatch`) |
| Localization | slang |

### Key Patterns Quick Reference

| Layer | Component | Pattern |
|-------|-----------|---------|
| Data | DTO | `fromRecord()` + `toEntity()` + `toCreateJson()` (static) |
| Data | Repository | Abstract interface + `FutureEither<T>` return types |
| Presentation | Controller | `AsyncNotifier` with `build()` + mutation methods returning `bool` |
| Presentation | Page/Widget | `AsyncValue.when()` for loading/error/data states |
| Presentation | Family Provider | `build(String id)` parameter for scoped state |
